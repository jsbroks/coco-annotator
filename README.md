# COCO Annotator（2026 升級版）

繁體中文 ｜ [English](README.en.md)

> 修改：**TsaiCC × Claude**

COCO Annotator 是一套網頁版的影像標註工具，用來製作物件偵測、實例分割、關鍵點等模型的訓練資料，標註結果以通用的 [COCO 格式](https://cocodataset.org/#format-data) 匯出。

這個版本是從 [jsbroks/coco-annotator](https://github.com/jsbroks/coco-annotator) fork 出來的，除了把整套技術升級到目前仍有維護的版本，也加上了旋轉物件框、Segment Anything、用自己的 YOLO 模型預標註等功能。

## 主要功能

- **多種標註方式：** 邊界框（BBox）、旋轉框、多邊形、筆刷、橡皮擦、魔術棒、關鍵點
- **旋轉物件框：** 三下點擊畫出任意角度的框，可旋轉、縮放、移動；可直接匯出 YOLO-OBB，或轉成 DOTA 格式訓練
- **Segment Anything（SAM 2.1）：** 點一下物體就自動切出輪廓
- **用自己訓練的 YOLO 模型預標註：** 支援 detect、OBB、segment、pose，可以標單張圖或整個資料集
- **多人共同標註與審核：** 分享資料集、平均指派圖片給成員；標註完送審，審核者通過或退回（附原因）；進度一目了然
- **資料集聊天室：** 每個資料集有自己的聊天室，在資料集頁和標註畫面都能開；可以附上目前這張圖，別人點一下就開到同一張；也能傳照片（📎、直接貼上或拖進來）和表情符號
- **在網頁上訓練模型：** 選一份 YOLO 匯出和模型（Ultralytics 支援的 YOLOv3u／v5u／v6／v8／v9／v10／11／12／26 與 RT-DETR，預訓練 `.pt` 或從頭訓練的 `.yaml`，也可以上傳自己的權重或架構檔），可加任意訓練參數或上傳 `args.yaml`，在伺服器的顯示卡上訓練，即時看 mAP 和損失曲線，訓練完的模型自動放進「模型」頁拿來預標註
- **網頁終端機（預設關閉）：** 開啟後，有權限的人用伺服器帳號密碼，直接在網頁登入伺服器的命令列
- **整張圖分類標籤：** 標註畫面一鍵設定整張圖的類別，做圖片分類資料集
- **資料集統計：** 每位成員標了多少、標註時間、類別分布、物件大小與位置、自動找出漏標、重複框、超出邊界等問題
- **影片匯入：** 一次上傳多支影片，顯示總長與總幀數，可以設定每支的開始與結束，每隔幾秒或每隔幾幀自動擷取一張影格
- **COCO / YOLO 格式匯入、匯出：** 兩種格式互轉，YOLO 支援 detect、segment、OBB、pose
- **介面語言：** English、繁體中文

## 安裝

需要一台裝好 [Docker](https://docs.docker.com/engine/install/)（含 Docker Compose）的 Linux 主機。

```bash
git clone -b upgrade-2026 https://github.com/Tsaicc-biovlsi/coco-annotator.git
cd coco-annotator
echo "SECRET_KEY=$(openssl rand -hex 32)" > .env
sudo docker compose up -d --build
```

完成後用瀏覽器打開 `http://伺服器IP:5000`。第一次開啟時會要求註冊，**第一個註冊的帳號會自動成為管理員**。

**更新：** `git pull` 後再執行一次 `sudo docker compose up -d --build`。還開著舊版頁面的使用者會在一分鐘內（或伺服器重啟、網路重新連上時）看到「系統已更新」提示，10 秒後自動重新整理，正在標註的內容會先存檔，不用一個一個通知大家重新整理。

### 啟用 AI 功能（SAM 與 YOLO 預標註）

AI 功能需要 PyTorch，預設不安裝，讓映像檔保持精簡。

**有 NVIDIA 顯示卡（建議）：**

1. 安裝 [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html)，並確認以下指令會印出顯示卡資訊：
   ```bash
   sudo docker run --rm --gpus all ubuntu nvidia-smi
   ```
2. 下載 SAM 模型，並讓 Docker Compose 每次都帶上 GPU 設定：
   ```bash
   ./models/download_sam.sh
   echo "COMPOSE_FILE=docker-compose.yml:docker-compose.gpu.yml" >> .env
   sudo docker compose up -d --build
   ```

**只有 CPU：**

```bash
./models/download_sam.sh
echo "SAM=cpu" >> .env
sudo docker compose up -d --build
```

用 CPU 也能運作，只是每張圖第一次使用 SAM 時要等幾秒，模型預標註也比較慢。

`download_sam.sh` 預設下載 SAM 2.1 base（約 320 MB）。只有 CPU 時可改下載較快的 tiny 版：`./models/download_sam.sh sam2.1_t`，並在 `.env` 加上 `SAM_CHECKPOINT=/models/sam2.1_t.pt`。其他選項：`sam2.1_s`、`sam2.1_l`（最準、約 900 MB），以及第一代的 `vit_b`、`vit_l`、`vit_h`。

**從第一代 SAM 升級：** 執行 `./models/download_sam.sh` 下載 SAM 2.1 後重新啟動即可。還沒下載前，伺服器會自動沿用 `models` 資料夾裡的第一代 SAM 檔案，功能不受影響。SAM 工具面板會顯示目前用的是哪個模型。

## 第一次使用

**最簡單的方式：** 在首頁按「匯入」，選「建立新資料集」並輸入名稱，再選圖片（或整個資料夾），有 COCO 標註檔的話一併選上，按「匯入」就完成了。圖片會上傳到伺服器，同名的檔案會略過。

**圖片很多時**（例如上萬張），直接放到伺服器上比較快：

1. **放圖片：** 在伺服器的 `datasets/` 底下建一個資料夾，把圖片放進去，例如 `datasets/baseball/0001.jpg`。
2. **建立資料集：** 在網頁「資料集」頁面按「建立資料集」，名稱填資料夾名稱（例如 `baseball`），並加入要用的類別。
3. **掃描：** 進入資料集，按左側的「掃描」，圖片就會出現。之後再放新圖片進資料夾，再按一次掃描即可。
4. **開始標註：** 點任一張圖片進入標註畫面：
   1. 在右側選一個類別，按 `+` 新增一個標註（或按空白鍵）。
   2. 從左側工具列選工具開始畫。
   3. 修改會**自動儲存**：停下來約 2 秒後就會存到伺服器，關閉或重新整理頁面前也會先存。也可以隨時按 `Ctrl+S` 手動儲存。

## 標註工具與快捷鍵

### 工具

| 工具 | 快捷鍵 | 用途 |
|---|---|---|
| 選取 | `S` | 選取、移動、調整既有的標註（BBox 和旋轉框可直接拖曳移動、縮放） |
| 邊界框 | `R` | 拖曳畫出矩形框 |
| 旋轉框 | `O` | 畫任意角度的框（見下方說明） |
| 多邊形 | `V` | 逐點畫出輪廓 |
| 魔術棒 | `W` | 依顏色相近程度自動選取區域 |
| 筆刷 / 橡皮擦 | `B` / `E` | 塗抹增加或擦除區域（`[` `]` 調整大小） |
| 關鍵點 | `K` | 在已有框的標註上標關鍵點 |
| SAM | `A` | AI 自動分割（見 [AI 輔助標註](#ai-輔助標註)） |

### 旋轉框怎麼畫

1. 點第一個角。
2. 點第二個角，這兩點就是框的一條邊。按住 `Shift` 可以讓角度吸附到 15° 的倍數。
3. 移動滑鼠拉出寬度，再點一下完成。按 `Esc` 取消。

畫好後可以拖曳圓形把手旋轉、拖曳角落縮放、在框內拖曳移動，也可以用方向鍵微調位置（`Shift` 加方向鍵一次移動 10 px）。

在畫面上點另一個旋轉框會選取它，就能調整它的角度和位置。要在既有的框裡面畫新框（例如物體重疊時），按住 `Ctrl` 再點第一個角。

### 關鍵點

關鍵點必須依附在框上：先為標註畫出 BBox 或旋轉框，關鍵點工具才會啟用。類別的關鍵點名稱與連線，在類別設定（齒輪）裡定義。

### 其他快捷鍵

| 快捷鍵 | 動作 |
|---|---|
| `空白鍵` | 新增標註 |
| `Backspace` | 刪除目前的標註 |
| `Ctrl+Z` | 復原（包含刪除標註、清除整張圖片的標註） |
| `Ctrl+S` | 儲存 |
| `N` / `P` | 下一張 / 上一張圖片 |
| `↑` `↓` | 在標註之間切換 |
| `→` `←` | 展開 / 收合類別 |
| `C` | 複製上一張圖片的全部標註（`Ctrl+Z` 可以復原） |
| `M` | 圖片置中 |
| `D` | 清除這張圖片的全部標註（不用確認，`Ctrl+Z` 可以復原） |

**點已有的形狀自動換工具：** 用邊界框或多邊形工具時，第一下點在已經畫好的形狀上，會自動換成畫那個形狀的工具（點矩形框→邊界框、點旋轉框→旋轉框、點多邊形→多邊形），不會開始畫新的。已經畫到一半時不會換。用**選取**工具點一下（不拖曳）資料集預計任務的形狀（例如旋轉框資料集裡的旋轉框、偵測資料集裡的矩形框），也會換成那個工具，可以直接接著調整或畫下一個；拖曳移動、按住左右鍵暫時選取、或按住 `Shift` 時不會換。

**雙擊形狀開設定：** 不管目前是哪個工具，在已經畫好的形狀上快速點兩下，就會選取它並打開它的設定視窗（顏色、名稱、類別、附加資訊、刪除）。兩下點擊不會留下點、框或空的標註；正在畫多邊形（已經點了幾個點）時快速點兩下不算，照常畫。

**左右鍵同時按＝暫時用選取工具：** 不管目前是哪個工具，在畫面上同時按住滑鼠左鍵和右鍵，就會暫時換成選取工具（可以點選、拖曳頂點或形狀）；兩個鍵都放開後回到原本的工具。先按左鍵時那一下不會留下多邊形的點或框。畫面上的右鍵不會跳出瀏覽器選單。

左側工具列還有：
- **用模型標註**（火箭圖示）
- **全部顯示 / 全部隱藏**
- **清除這張圖片的標註**（⊗ 圖示，或按 `D`）：不用確認，直接清除；按 `Ctrl+Z` 馬上復原，或之後到「活動紀錄」的垃圾桶救回。

## 上層類別

類別可以有上層類別（父類別），而且**一個類別可以屬於多個上層類別**，例如 `car` 同時在「交通工具」和「陸地」下。在類別頁面新增或編輯類別時，直接點選已有的上層類別（可多選）；清單裡沒有的才在下方輸入名稱新增。

- **多層**：上層類別可以有很多層，用「/」分隔，例如上層類別填「交通工具/陸地」，就會放在「交通工具」裡的「陸地」。
- **同名類別**：同一個名字可以放在不同的上層類別底下，而且彼此獨立（例如「場景/路口」和「場景/走廊」底下都可以有自己的「人」，顏色、標註都分開）；同一個上層類別底下不能重複。
- **類別頁面**左邊是資料夾樹（例如 交通工具 › 陸地 › …，可展開收合，數字是底下的類別數），右邊是目前資料夾的類別（可選「包含下層」）和裡面的子資料夾，每頁 16 個；可以搜尋，也能直接在目前資料夾下新增類別，會記住上次看的位置。
- **資料集頁面**依最上層分頁，分頁下方可以再點進下一層；另有「全部」和「沒有上層類別」，可以搜尋名稱，每頁 8 個。
- **建立資料集**的「預設類別」和**匯出**的類別清單上方有「依上層類別帶入」：點一下就勾選該上層類別下的全部類別，再點一次取消。
- **標註畫面**右側的類別清單也依上層類別分段顯示（以第一個上層類別為準）。
- 匯出 COCO 時第一個上層類別寫在 `supercategory`，全部寫在 `supercategories`；匯入 COCO 時新建的類別會帶入這兩個欄位。

## 活動紀錄與垃圾桶

上方選單的「活動紀錄」記下每個人做的每個動作，最新的在最上面、按日期分段：

- **標註**：同一個人在同一張圖連續標註會合成一筆，例如「在 a.jpg 新增 3 個標註、修改 2 個標註」，附上標出那些形狀的縮圖，按「開啟」直接進標註畫面。也包含整張圖類別、複製標註、用模型自動標註。
- **匯入匯出**：COCO / YOLO 匯入、影片匯入、上傳圖片、掃描資料夾、匯出。匯入（以及整個資料集的模型自動標註）可以按「**撤銷匯入**」，把那次建立的標註（影片則是畫格）一次移到垃圾桶。
- **刪除與還原**：每次刪除算一筆，例如「清除這張圖片的標註」刪掉的 5 個標註會合成一筆並列出各類別數量；可以直接在那一筆按「還原」或「永久刪除」，也能展開逐個還原。還原標註時，如果它所屬的圖片或資料集也被刪了，會詢問是否一起還原。
- 刪除資料集後想用**同一個名稱**再建立：建立視窗會提示垃圾桶裡有同名資料集，可以直接「還原原本的資料集」，或「用這個名稱建立新的資料集」（舊的標註紀錄永久刪除，資料夾裡的圖片保留並自動加入新資料集）。同名的類別在垃圾桶裡時，再建立一次會直接把它還原。
- **垃圾桶**分頁只列出還沒還原、還沒永久刪除的項目，可以勾選多筆一起處理，或「清空垃圾桶」。永久刪除圖片時，伺服器上的圖片檔也會一起刪除。
- **資料集與類別**、**審核**：建立 / 修改資料集、成員、類別改名，以及送審、核准、退回（含退回原因）、分配圖片。
- **帳號與管理**：建立、批次建立、修改（改名、重設密碼、換身分）、刪除帳號；新增、修改、刪除身分；上傳、修改、刪除模型；自己變更密碼；刪除或清除任務。
- 可以依資料集、操作者篩選，或搜尋檔名、類別名稱。
- 紀錄和垃圾桶裡的項目保留 **90 天**後自動清除（可用 `TRASH_DAYS` 調整，`0` 表示永久保留）。這個版本之前做的動作沒有紀錄；之前刪除的項目會出現在垃圾桶，操作者顯示「未記錄」。
- 要有「活動紀錄」權限的身分才看得到這頁（見下方「身分」）。看得到的話，是自己資料集裡的紀錄；管理員看得到全部。

## AI 輔助標註

需要先[啟用 AI 功能](#啟用-ai-功能sam-與-yolo-預標註)。

### Segment Anything（SAM 2.1）

選取一個標註，按 `A` 切到 SAM 工具（面板會顯示目前的模型，例如「SAM 2.1 b」）：

- 點物體（綠點）：自動切出輪廓。
- `Shift` + 點擊（紅點）：排除不要的部分。
- 也可以直接拖一個框把物體框起來。
- 按 `Enter` 套用。

### 用自己訓練的 YOLO 模型預標註

支援 Ultralytics YOLO（YOLOv8、YOLO11 以後的版本）的四種模型：

| 模型類型 | 產生的標註 |
|---|---|
| detect | 物件框 |
| obb | 旋轉框 |
| segment | 多邊形 |
| pose | 物件框 + 關鍵點 |

**放入模型（二選一）：**
- 管理員（或有「管理模型」權限的身分）在上方選單的「**模型**」頁上傳 `.pt` 檔。
- 把 `.pt` 檔複製到伺服器的 `models/` 資料夾，不需要重啟。

**「模型」頁：** 列出所有模型，顯示類型、類別、檔案大小、上傳者，以及用過幾次、產生了多少標註、上次誰在什麼時候用的。管理員或有「管理模型」權限的身分可以：
- **開關**：關掉的模型不會出現在「用模型標註」的選單，也不能被執行（檔案還在，隨時可以再開）。
- **顯示名稱和備註**：例如把 `best.pt` 顯示成「棒球偵測 v2」，備註寫訓練資料或適用場景；選模型時會看到。
- **預設信心值**：選到這個模型時，信心值自動設成這個數字。
- **下載**（備份）和**刪除**。
有「模型」頁面權限的人可以看，但不能修改；沒有的話看不到這頁（仍然可以在標註畫面執行已開啟的模型）。頁面上方也會顯示運算裝置（GPU / CPU）和 SAM 是否可用。

**使用：**
- **單張圖：** 標註畫面左側的火箭圖示 → 選模型、調整最低信心分數 → 執行。
- **整個資料集：** 資料集頁面左側的「用模型預標註」，在背景執行，進度顯示在「任務」頁面；可以選擇略過已經有標註的圖片。

模型的類別會依名稱（不分大小寫）對應到資料集的類別，缺少的類別可以選擇自動建立。預測結果是一般的標註，可以再人工修正。

> ⚠️ 載入 `.pt` 檔時會執行檔案裡的程式碼，只放你信任來源的模型。這也是為什麼只有管理員能上傳。

## 在網頁上訓練模型

上方選單的「**訓練**」（管理員，或有「訓練模型」權限的身分）。訓練由獨立的 `annotator_trainer` 容器執行，一次跑一個，其他的排隊。

1. **先匯出：** 在資料集匯出 **YOLO**，勾「zip 裡附上圖片」，建議切分出驗證集（沒切分時驗證用的是同一批訓練圖，分數會偏高）。匯出紀錄的 YOLO 匯出旁邊有「用這份訓練」可以直接過去。
2. **選模型：** 三種起點：
    - **官方模型：** 列出伺服器上的 Ultralytics 能訓練的所有系列——YOLO26、YOLO12、YOLO11、YOLOv10、YOLOv9、YOLOv8、YOLOv6、YOLOv5u、YOLOv3u、RT-DETR，只顯示符合匯出任務（detect／segment／obb／pose／classify）的模型。可選 **預訓練權重 `.pt`**（例如 `yolo26s.pt`，第一次用時伺服器自動下載，需要能連外網）或 **從頭訓練 `.yaml`**（例如 `yolo26s.yaml`、`yolov8m-p2.yaml`，權重隨機開始；可另外選一個預訓練權重載入，等於 `pretrained=yolo26s.pt`）。
    - **「模型」頁的模型：** 例如上次訓練的，加了新資料後繼續訓練。
    - **上傳的模型：** 上傳自己的 `.pt` 權重或 Ultralytics 模型架構 `.yaml`（要有 `backbone` 與 `head`；檔名含 n／s／m／l／x 例如 `my-yolo26s.yaml` 會用那個大小）。上傳的 `.yaml` 一樣可以選預訓練權重載入（官方的或上傳的 `.pt`）。上傳的檔案存在 `models/.training/uploads/`，大家共用，上傳者或管理員可刪除。
3. **設定參數：** epochs、圖片大小、batch（-1＝依顯示卡記憶體自動，0.7＝用 70% 記憶體）、patience（連續幾輪沒進步就提早停）。「**進階參數**」列出伺服器上 Ultralytics 的全部訓練參數（約 70 個），分成優化器與學習率、資料增強、損失權重、資料、執行與儲存等組，每個都有中文說明和預設值，直接改值即可；改過的會以藍底標示並送出，清空或按還原就回到預設，也可以搜尋或只看已修改的。或 **上傳 `args.yaml`**（例如之前訓練留下的 `runs/train/args.yaml`）一次帶入：能用的參數會填進來，`model`、`data`、`project`、`name` 等由系統決定的會略過並列出。下方會顯示實際執行的指令。檔案路徑類的值不接受（資料與輸出位置由系統設定）。
4. **資料增強：** 選好匯出後會列出這次訓練用到的增強，分兩部分：**匯出時**已做好、存在 zip 裡的（例如每張訓練圖 +2 張：水平翻轉、小角度旋轉 ±15°），以及 **訓練時** Ultralytics 每一輪隨機套用的（馬賽克、左右翻轉、平移、縮放、色調／飽和度／亮度…，顯示實際的值；只列該任務會用的，例如 copy_paste 只有分割、auto_augment／erasing 只有分類）。沒啟用的以刪除線列出；用進階參數改過的會加框。點任一項就會在進階參數加上那個參數讓你改值；匯出和訓練都做同一種增強（例如都有翻轉）時會提醒。訓練紀錄展開後也看得到這次用的增強。
5. **看進度：** 訓練紀錄列出排隊、訓練中、完成、失敗、已停止；展開後是像 TensorBoard 的曲線：每個指標一張圖（precision、recall、mAP50、mAP50-95，分割／姿態會分框和遮罩／關鍵點），每種損失一張圖，訓練損失 **每個批次都有點**（取自訓練進度條，不只每輪一點），和驗證損失畫在一起比較；另有學習率、顯示卡記憶體、每輪花費時間。上方「平滑」滑桿和 TensorBoard 一樣（淡色是原始值、深色是平滑後），滑鼠移上去看那個位置各條線的值。**最佳的是哪一輪：** 訓練紀錄列出最佳那輪的分數（例如「★ mAP50-95 0.084 @7」），展開後最上方顯示最佳是第幾輪和它的各項指標、之後幾輪沒有進步（連續 patience 輪沒進步就提早停止），每張曲線也用虛線標出那一輪。判斷方式和 Ultralytics 挑 `best.pt` 一樣（目前版本依 mAP50-95；分割／姿態把框和遮罩／關鍵點相加；分類取 top-1 與 top-5 平均），存到「模型」頁的就是這一輪。訓練輸出與曲線都是即時推送（訓練一印出來就看得到）。可以停止（到目前最好的權重仍會保留）或取消排隊。
    **中斷後繼續：** 停止或失敗的訓練只要有完成過至少一輪，展開後會有「從第 N 輪之後繼續」，用最後完成那一輪的權重和狀態（`last.pt`，含優化器與學習率排程）接著訓練，參數和資料都不變，曲線接在後面。**伺服器重開、斷電或訓練容器重啟** 時，訓練中的那筆會自動重新排隊並從中斷處接續（`annotator_trainer` 設為 `restart: unless-stopped`，開機後 Docker 會自動啟動它），沒完成任何一輪的才標為失敗。被切斷的那一輪會從頭重跑。
**沿用之前的設定：** 展開任何一筆訓練紀錄按「用這次的設定」，就會把那次的模型（含載入的預訓練權重）、epochs、imgsz、batch、patience、進階參數和訓練伺服器帶入上方的新訓練，可以再改；匯出或模型已不在時會提醒重選。
6. **結果：** 完成後最好的權重（`best.pt`）自動存成「模型」頁的 `trained/<資料集>-<任務>-run<編號>.pt`，可以直接用來預標註。訓練結束（完成、停止或失敗）時，Ultralytics 在 `runs/train/` 產生的所有東西會自動打包成 zip：`weights/best.pt`、`weights/last.pt`、`results.csv`、`args.yaml`、各種圖（混淆矩陣、PR／F1 曲線、`results.png`、訓練與驗證圖片範例）和訓練輸出 `train.log`；展開訓練紀錄按「下載訓練結果 .zip」即可下載（更新前的訓練第一次下載時才打包）。壓縮檔放在 `models/.training/run-<編號>/`，刪除訓練紀錄時一併刪除。

**部署：** 訓練需要 Ultralytics（以 `SAM=cuda` 或 `SAM=cpu` 建置的映像檔才有）和顯示卡：

```bash
sudo docker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d --build
```

會多一個 `annotator_trainer` 容器（與網站共用同一個映像檔、`models/` 與 `datasets/` 資料夾）。訓練頁右上角會顯示訓練服務是否在執行、用哪張顯示卡。訓練的暫存檔在 `models/.training/`（不會出現在模型頁），訓練紀錄刪除時一併刪除，已存到模型頁的模型不受影響。訓練用的資料載入器需要共用記憶體，預設給 8 GB（`.env` 的 `TRAIN_SHM` 可調）。沒有獨立容器時，也可以在網站容器加環境變數 `TRAINER_EMBEDDED=true` 讓網站自己訓練。

### 用其他伺服器訓練

內網的其他伺服器也可以用它的顯示卡幫忙訓練，幾台就能同時跑幾個訓練。訓練頁右上角列出每一台訓練服務（這台叫 `main`，`.env` 的 `TRAINER_NAME` 可改）：顯示卡、閒置／訓練中 #N／離線。

1. **新增（管理員）：** 訓練頁 → 「訓練伺服器」→ 輸入名稱（例如 `gpu2`）→ 新增。畫面會給一組 token（只顯示這一次）和要在那台伺服器上執行的指令。
2. **在那台伺服器上：** 需要 Docker 與 NVIDIA Container Toolkit，不用裝網站、資料庫。照畫面上的指令：

    ```bash
    git clone -b upgrade-2026 https://github.com/Tsaicc-biovlsi/coco-annotator.git coco-annotator
    cd coco-annotator
    cat > .env <<'EOF'
    TRAINER_URL=http://<這台網站伺服器的內網 IP>:5000
    TRAINER_TOKEN=<token>
    EOF
    sudo docker compose -f docker-compose.worker.yml up -d
    ```

    **不用建置映像檔：** 它直接用 Ultralytics 官方映像檔（`ultralytics/ultralytics`，內含 PyTorch、CUDA、Ultralytics），程式碼從這個資料夾掛進去，所以第一次只要下載映像檔，之後更新只要 `git pull` 再 `sudo docker compose -f docker-compose.worker.yml restart`。想要更快或固定版本：`.env` 加 `WORKER_IMAGE=`（例如 `ultralytics/ultralytics:<版本>`）；或從已經有映像檔的伺服器經內網複製過去，免得每台都上網下載：

    ```bash
    # 在已經有的那台（例如網站伺服器，映像檔叫 coco-annotator-webserver）
    sudo docker save coco-annotator-webserver | gzip > annotator-image.tar.gz
    scp annotator-image.tar.gz 帳號@新伺服器IP:~/
    # 在新的那台
    gunzip -c ~/annotator-image.tar.gz | sudo docker load
    echo "WORKER_IMAGE=coco-annotator-webserver" >> .env
    ```

    匯出檔也會留在那台（`./worker/.cache/exports/`，`WORKER_CACHE_GB` 預設 30 GB，滿了先刪最久沒用的），同一份匯出再訓練就不必重新下載；用到的模型檔（官方權重、上傳的模型）也留著（`./worker/.cache/files/`）。

    它只跑一個 `annotator_trainer_worker` 容器，主動連到網站（網站不需要那台的帳號密碼，也不用替它開任何 port），連上後在訓練頁顯示為「gpu2 · 顯示卡名稱 · 閒置」。
3. **指定在哪台訓練：** 新訓練的「在哪台訓練」選某一台就只由那台訓練；選「任何空著的」（預設）就由先空出來的那台接。訓練紀錄會標示在哪台跑（`· gpu2`），排隊中指定了的顯示 `→ gpu2`。

**那台電腦自己也在用 GPU 時：** 每台訓練伺服器（包括這台）每幾秒用 `nvidia-smi` 看一次顯示卡。沒在跑網站的訓練、卻有大量顯示記憶體被占用（預設 2 GB 以上，桌面本身只用幾百 MB），或使用率連續幾次超過 50%，就當作「GPU 使用中（非本站）」：訓練頁那台顯示成橘色，滑過去看得到占用的程式；它不會接排隊的訓練，「任何空著的」會交給真的空著的那台，指定給它的會顯示「等 GPU 空出來」，空出來後自動開始。門檻可在那台的 `.env` 調：`GPU_BUSY_MEMORY_MB`、`GPU_BUSY_UTIL`；`GPU_BUSY_CHECK=false` 只顯示、不擋。容器內沒有 `nvidia-smi` 時不會擋（`docker-compose.worker.yml` 已設好 `NVIDIA_DRIVER_CAPABILITIES`）。

在其他伺服器上的訓練，網頁上看到的都和本機一樣：即時輸出與曲線、最佳輪數、停止、刪除、下載訓練結果 .zip；完成後模型傳回這台、放進「模型」頁。訓練資料（匯出檔）、上傳的模型和這台已下載過的官方權重都由網站傳過去，所以那台不一定要能連外網（沒下載過的官方權重則需要）。**中斷後繼續** 只能在原本那台接續（`last.pt` 留在那台的 `./worker/`），所以「繼續」會自動指定回那台；那台重開後，訓練中的那筆會自動排隊接續。完成的訓練不會留在那台。

**`TRAINER_URL`** 用那台連得到的網站位址：內網 IP（`http://192.168.x.x:5000`，最快）或網站的網址（`https://…`）都可以。經過反向代理也沒關係：訓練結果（模型、結果壓縮檔）是分成每塊 8 MB 傳回的，不受代理的上傳大小限制，斷掉的那一塊會重送；真的傳不到時，檔案留在那台的 `./worker/`。開始訓練前那台要先下載匯出檔（增強過的匯出可能有好幾 GB），訓練輸出會顯示下載進度；這段時間按停止也會立刻放棄下載。那台關機或連不上時按停止／刪除會直接生效。

管理：「重新產生 token」會讓舊的立刻失效（那台的 `.env` 要換新的再 `up -d`）；「移除」後那台不能再接訓練，指定給它而還在排隊的訓練改成任何空著的接。

## 網頁終端機

**預設關閉**：沒有頁面、選單，也不能在身分裡勾這個權限，網站不會發出任何 SSH 連線，伺服器也不用開放 22 port。要使用時在 `.env` 加 `TERMINAL_ENABLED=true` 再 `sudo docker compose up -d`。

開啟後，上方選單的「**終端機**」（管理員，或有「網頁終端機」權限的身分）可以用**伺服器本身的帳號密碼**登入 A server 的命令列（SSH），支援中文、顏色、調整視窗大小；選取文字即可複製。帳號密碼只用來登入這一次，不會被儲存；每次登入都會記在活動紀錄；超過 60 分鐘沒有操作自動斷線（`TERMINAL_IDLE_MINUTES` 可調，0＝不斷線）。

> ⚠️ 登入後等於可以操作整台伺服器，只把這個權限給信任的人。

**伺服器需要：**
- 開著 SSH 服務（`sudo apt install openssh-server`），並允許密碼登入。
- 網站容器透過 `host.docker.internal` 連到伺服器本身（`docker-compose.yml` 已設定 `extra_hosts`）。如果有防火牆（例如 ufw），要允許 Docker 網段連到 22 port：`sudo ufw allow from 172.16.0.0/12 to any port 22`。
- 要登入別台或其他 port，在 `.env` 設 `TERMINAL_SSH_HOST`、`TERMINAL_SSH_PORT`（只能連這一台，使用者不能自己輸入主機）。

## 帳號、權限與共同標註

- **身分：** 每個帳號有一個身分，在「管理 → 身分」分頁設定。內建兩個：
  - **管理員**：什麼都能做，不能修改。
  - **一般使用者**：新帳號的預設身分，只看得到自己建立的資料集和別人分享給他的資料集。可以勾選它的權限。
  - 管理員可以**新增自己的身分**（例如「助教」），勾選它能做什麼：
    - 頁面：**活動紀錄**、**模型**、**任務**（沒有任務權限的人仍會在資料集頁看到自己工作的進度）。
    - 管理：**管理模型**（上傳、開關、改名、刪除）、**管理使用者**（進管理面板新增、編輯、刪除非管理員帳號，但不能設定管理員、不能改自己的身分；只能指派權限不超過自己的身分、只能編輯或重設權限不超過自己的帳號，批次建立時只能加進自己擁有的資料集）、**看全部資料集**（像管理員一樣看得到，但只能看：新增、修改、刪除標註或資料集仍須是成員）、**訓練模型**（「訓練」頁）、**網頁終端機**（「終端機」頁，等於能操作整台伺服器；`TERMINAL_ENABLED=true` 時才有這個選項）。
    - 其他規則：類別的名稱、顏色等設定只有建立者（或管理員）能改；把人從資料集成員移除時，他的審核者身分也一併移除；圖片永久刪除只有資料集擁有者能做。
  - 在「使用者」分頁的「身分」欄直接選就能換；刪除身分時，該身分的人會改回一般使用者。
- **聊天室：** 每個資料集的成員共用一個聊天室。資料集頁右下角、標註畫面左下角的 💬 按鈕打開；Enter 送出，Shift+Enter 換行。在標註畫面按 🖼 可以附上目前這張圖，別人點訊息裡的檔名就會開到那張圖。**照片：** 按 📎 選照片（一則最多 6 張），或直接把截圖貼上（Ctrl+V）、把檔案拖進聊天室；送出前可以預覽、移除。照片存在資料集資料夾的 `.chat/` 裡，最大 2560 px，會轉正並去掉拍攝地點等資訊；點照片看大圖。只有資料集成員看得到。**表情符號：** 按 😊 開表情面板（表情、手勢、符號、物品、動物、食物，第一頁是最近用過的）。聊天室關著時有新訊息，按鈕上會顯示未讀數，並短暫跳出預覽。
- **分享資料集：** 在資料集卡片右下角的 **⋮** 選單選「分享」，輸入成員的使用者名稱，再按「儲存」。
- **第一次登入要改密碼：** 由管理員設定密碼的帳號（批次建立、在管理面板新增、或被管理員重設密碼），登入後會先跳出視窗要求換成自己的密碼（不能跟原本一樣，至少 5 個字元），改完會自動登出，再用新密碼登入。
- **關閉公開註冊：** 在 `.env` 加上 `ALLOW_REGISTRATION=false`，再執行 `sudo docker compose up -d`。之後只能由管理員建立帳號。

**附加資訊：** 每個標註、圖片都可以加上自訂的「名稱 → 值」欄位，例如 `occluded: true`、`note: 被遮擋`。匯出時會跟著輸出，方便之後篩選資料。資料集設定裡可以設定每個新標註預設帶有的欄位。

## 預計任務

建立資料集時可以選「預計任務」：未指定、物件偵測、實例分割、旋轉框、姿態 / 關鍵點、圖片分類、語意分割（從首頁「匯入」建立新資料集時也能選，之後可在資料集「設定」修改）。它會：

- 第一次打開標註畫面時，預先選好對應的工具（框、多邊形、旋轉框、關鍵點）；
- 匯出時預設選好 YOLO 和對應的標註類型；
- 只在「圖片分類」（或未指定）時顯示「整張圖類別」；
- 讓統計頁多檢查不符合任務的標註，例如旋轉框任務裡的水平框、姿態任務裡沒有關鍵點的標註、分類任務裡還沒設類別的圖。

所有工具仍然都能用，已有的標註也不受影響。

## 審核流程

每張圖有四種狀態：**未標註 → 待審核 → 已審核**，或被**退回**。

0. **成員：** 資料集頁面的「成員」分頁，擁有者可以搜尋帳號或姓名邀請成員，也可以一次貼上多個帳號（例如從 Excel 複製一欄學號）；找不到的帳號會標紅（請先到管理面板建立）。成員列表會標示擁有者、審核者和最後上線時間，擁有者可以把人移出資料集（他的審核者身分一併移除）。
1. **指派：** 資料集頁面的「進度與審核」分頁，勾選成員後按「平均分給 N 人」，依檔名順序把圖片切成連續的區段，每人一段。可以只分配還沒指派的、未完成的，或全部重新分配。
   - **依資料夾分配：** 切到「依資料夾」，每個子資料夾（例如一部影片切出來的圖）整個交給同一個人。按「自動分配給勾選的 N 人」會在不拆開資料夾的前提下讓每人的張數盡量平均（大的資料夾先分給目前最少的人），也可以逐列自己選或選「取消指派」，下方會顯示分配後每人幾張，確認後按「套用」。
   - **清除某個人的指派：** 「各成員進度」表每一列右邊有「清除指派」，可以選「只清除還沒完成的」（未標註和被退回的，已送審、已審核的仍算他的）或「全部清除」。清掉的圖會回到「未指派」，可以再分給別人，例如有人中途退出時。
   - **各資料夾進度：** 有子資料夾時，「進度與審核」分頁會列出每個資料夾的張數、負責人、各狀態張數和進度條。負責人整個資料夾都是同一人時寫成 `test03(all)`，多人分時寫成 `test01(21) test02(43)`，還沒指派的部分寫成 `未指派(5)`。
2. **標註：** 成員按「標註我的圖」直接開始；標完按右側的「標註完成，送審」。擁有者和審核者自己標的圖不用送審：他們的按鈕是「標註完成（直接核准）」，按下就是已核准。習慣直接按 `N` 換下一張的人，可以打開右側的「自動送審」開關（每個人自己設定，預設關閉）：按 `N` 或 `→` 換下一張時，還沒送審（或被退回）的圖會在換頁時自動送審。
   - **空白圖：** 沒有任何標註的圖，按 `N`（或按「標註完成」）會先跳出「這張圖是空白的嗎？」：`Enter` 確認是空白圖並送審、`Esc` 留在這張繼續標、再按一次 `N` 先跳過不送審。確認過的空白圖，「統計」的「可能的問題」不會再列為沒標註的圖，而是另外列出「已確認是空白圖」幾張（被退回的話會再算回沒標註）。
3. **審核：** 審核者按「開始審核」（或從資料集進「快速審核」），逐張「通過」或「退回」（填寫原因，標註者會在圖上看到）。
4. **匯出：** 匯出第 3 步勾「只匯出已審核的圖片」。

審核者只有資料集的建立者，以及建立者在「進度與審核」分頁勾選的成員；**管理員不會因為是管理員就能審核**（也不能幫自己加成審核者），但仍可以分配圖片。圖片頁左側可以依「狀態」「負責人」篩選，圖片卡片上也會顯示狀態。「狀態」另外可以選「已標註」（有任何標註，不管審核狀態）和「AI 標註」（有模型標的標註）；有模型標註的圖片卡片會多一個紫色「AI」標籤。

**快速審核：** 資料集「進度與審核」分頁的「快速審核」會開一個專門審核的畫面，圖片直接畫上標註，可以切換一次看 1、4、9、16 張（按鈕或數字鍵 1–4，會記住）。每張圖下方有核准／退回／開啟標註；滾輪在游標所在的位置縮放，預設「同步縮放」：這頁所有圖片一起縮放到同一個位置、拖曳時一起移動（按住 `Shift` 只動那一張；上方開關可以關掉同步），`0` 還原；鍵盤：方向鍵選圖、`Y` 核准、`X` 退回（輸入原因後 Enter）、`Shift+Y` 核准這頁全部、`Enter` 或雙擊開啟標註畫面、`H` 顯示／隱藏標註、`N`／`P` 換頁。**類別：** 照片上只畫標註的形狀和顏色，不寫字；上方工具列列出這一頁用到的類別和數量（滑鼠停在某個標註上會顯示它的類別，每張圖各自的數量則停在下方「N 個標註」上顯示）。滑鼠移到某個標註或工具列的類別上，**畫面中所有圖片**都只亮那一類；點工具列的類別可以固定（被選的類別會以它的顏色標示，換頁也保留，再點一次、按 ✕ 或 `Esc` 取消；類別很多時可以用滑鼠滾輪左右捲動），方便一類一類檢查有沒有標錯。

**在快速審核裡直接修正：** 審核者點一下標註，會跳出小選單：選別的類別（可以打字搜尋、↑↓ 選、Enter 確定）就直接改好，或按「刪除這個標註」（刪掉的會進垃圾桶，可以復原）。類別標錯這種小問題可以當場改完再核准，不用退回。

**退回時標出問題位置：** 在快速審核按退回（`X`）後，直接在圖上拖曳就能框出有問題的位置，可以框好幾個（「復原上一個框」可以撤銷）；在標註畫面退回時，勾「附上目前放大的位置」就會把目前放大的範圍附上（先放大到有問題的地方再退回）。標註者打開被退回的圖時會看到紅色虛線框，右側也有「看標出的問題位置」按鈕可以直接跳過去。核准後框會自動清掉。

**常用退回原因：** 退回原因欄下方會列出常用原因（預設：類別標錯、框不完整或太大、有漏標、多標了不該標的），點一下就填入，原因欄空白時也可以直接按數字鍵 `1`–`9`。可以點多個，也可以再補充文字。輸入的原因按「存成常用」就會加進列表，按 ✏️ 可以移除；每個人的常用原因各自保存，最多 9 個。

**審核快捷鍵：** `Y` 核准（審核者）／標註完成（標註者），依這張圖目前能做的動作決定；`X` 打開退回原因欄，寫完按 `Ctrl+Enter` 送出、`Esc` 取消。

**不確定怎麼標？求助：** 先把畫面放大到有問題的地方，再按標註畫面右側的「不確定怎麼標？求助」。會列出這個資料集的建立者和審核者，綠點表示目前在線上（預設勾選在線上的人）；說明可以不寫，直接送出。對方不管在哪個頁面都會馬上跳出通知，點一下就打開那張圖，並自動放大到同一個位置、用黃色虛線框標出來，可以直接動手標註修正，再按「已處理，通知對方」；提問的人會立刻收到通知。右上角的救生圈圖示列出問我的、以及我問過且已處理／回覆的問題。沒人在線上時問題會留著，對方下次上線就看得到。提問和處理也會記在活動紀錄的「審核」分頁。

**只看某一類：** 標註畫面右側每個類別有一個 ⌖ 圖示，點一下就只看這一類，其他類別的標註變淡（上方會顯示「只看：…」，按 ✕ 取消）；滑鼠移到類別名稱上也會暫時只看那一類。換到同一個資料集的下一張圖時會保留，方便送審前一類一類檢查有沒有標錯。

**整張圖類別（圖片分類）：** 標註畫面右側的「整張圖類別」點一下類別即可設定，再點一次取消；可開「選好後自動跳下一張」快速標。匯出 YOLO classify 時以這個為準。

## 資料集統計

資料集頁面的「統計」分頁上方是總數（圖片、有標註的圖片、標註、平均每張、類別、成員、標註時間），接著自動檢查：沒有標註的圖、沒有或太少標註的類別、類別數量差距過大、疑似重複的框、超出圖片邊界或過小的框，並列出例子（點檔名直接開啟）。也有類別分布、每位成員標了多少（模型和匯入的另外列出）、**各成員標註時間**（總時間、近 7 天、處理過幾張圖、平均每張、最後標註；只算在標註畫面開著圖片的時間；超過 3 分鐘沒動滑鼠或鍵盤時，從最後一次動作起都不算（閒置的 3 分鐘也扣掉），切到別的分頁也暫停計時）、每張圖物件數、物件大小（COCO 小 / 中 / 大）、長寬比、物件位置熱度圖和圖片尺寸。

## 匯入與匯出

- **匯出：** 資料集列表頁上方的「匯出」（或資料集頁面的「匯出 COCO / YOLO」）打開匯出精靈，共 7 步：選取資料集 → 格式 → 資料夾名稱（YOLO）→ 類別 → 切分 → 資料增強 → 輸出確認。完成後在該資料集的「匯出紀錄」分頁下載（從列表頁匯出時，按鈕會顯示進度，完成後按「匯出完成，前往下載」直接過去）。下載時會顯示進度條、已下載／總大小和速度，可以按 ✕ 取消；超過 1.5 GB 的檔案直接交給瀏覽器下載（進度在瀏覽器的下載列）。
  - **選取資料集：** 從資料集頁面打開時已勾好那個資料集，直接從第 2 步開始。勾多個就合併成一份：第一個勾的是「主要」資料集，匯出紀錄放在它那裡（也會出現在其他被合併的資料集，標示「合併 N 個資料集」）。名稱相同的類別（不分大小寫）合併成同一類，只有部分資料集有的類別會標示「只有 XX 有」；類別不同的資料集旁邊會提醒。合併時檔名前面一律加上各自的資料集名稱，同名檔案不會互相覆蓋；切分、資料增強、只匯出已審核等設定對合併後的全部圖片一起處理。只列出你可以匯出的（你建立的）資料集。
  - **COCO：** 一個 json 檔。
  - **YOLO：** 一個 zip，最上層是 `data.yaml`、`classes.txt` 和一個由匯出者命名的資料夾（預設為資料集名稱），資料夾裡是 `train/labels/*.txt`（可勾選連圖片一起打包到 `train/images/`），解壓後就能用 `yolo train data=data.yaml` 訓練。標註類型：

    | 類型 | 輸出 | 說明 |
    |---|---|---|
    | detect | `class xc yc w h` | 每個標註的外接水平框 |
    | segment | `class x1 y1 … xn yn` | 多邊形；分成好幾塊的會接成一個多邊形 |
    | obb | `class x1 y1 … x4 y4` | 旋轉框照原本的 4 個角；其他標註用最小外接旋轉矩形 |
    | pose | `class xc yc w h px py v …` | 只輸出有關鍵點的標註，`data.yaml` 含 `kpt_shape`、`flip_idx` |
    | classify | `資料夾/train/<類別>/圖片` | 整張圖一個類別：以標註畫面設定的「整張圖類別」為準，沒設的圖看標註（只有一種類別才會匯出）；一定附圖片；不切分時 Ultralytics 會自動切 80/20；類別編號依資料夾名稱字母排序 |
    | semantic | `資料夾/train/masks/*.png` | 把框和多邊形畫成遮罩（像素值＝類別編號），0 是 background，你的類別從 1 開始；data.yaml 含 `masks_dir: masks` |

  - **檔名含資料集名稱：** YOLO 匯出的圖片和標註檔一律命名為「資料集名稱_原檔名」（例如 `ships_IMG_0001.jpg`、`ships_IMG_0001.txt`），合併多個資料集訓練時不會撞名；匯入回本系統時一樣對得到原圖。
  - **切分訓練 / 驗證 / 測試集：** 匯出時勾選「切分成訓練 / 驗證 / 測試集」，設定比例（例如 70 / 20 / 10，有常用比例可點）和亂數種子。以圖片為單位隨機分配，同樣的種子每次切出來都一樣。YOLO 的自訂資料夾裡會是 `train/images`、`train/labels`、`val/images`、`val/labels`、`test/…`，沒分到圖片的組不會寫進 data.yaml，`data.yaml` 自動指到各組；COCO 會變成內含 `train.json`、`val.json`、`test.json` 的 zip。不切分時，YOLO 全部放在 `資料夾/train/`，data.yaml 的 train 和 val 都指向它。
  - **資料增強：** 匯出精靈的第 6 步。增強可選，不勾就只輸出原圖。勾選後選每張圖多產生幾張（1–5）和要用的方式：水平翻轉、垂直翻轉、旋轉 90°、小角度旋轉（±5°–45°，畫布會放大不切掉物件）、放大裁切（裁一塊再放大回原尺寸）、亮度／對比／色調、曝光（大幅變暗或變亮）、灰階、隨機遮擋（1–4 塊灰色方塊，物體被蓋住超過 6 成就不標）、動態模糊、模糊、雜訊、JPEG 壓縮（模擬影片截圖的畫質）。匯出 YOLO 時，Ultralytics 訓練時預設就會做的（水平翻轉、色彩、縮放）會標示「匯出時不一定需要」，可以在訓練指令開啟的（垂直翻轉 `flipud`、旋轉 `degrees`）會顯示參數；曝光、灰階、遮擋、動態模糊、雜訊、JPEG 壓縮、旋轉 90° 是 YOLO 訓練不會做的，匯出時做最有幫助。每張增強圖隨機套用勾選的方式（至少一種），框、多邊形、旋轉框、關鍵點都會跟著正確轉換（水平翻轉時名稱含 left／right 或 左／右 的關鍵點會互換），被裁掉大半的物件會移除。**先以原圖切分，預設只增強訓練集**，驗證集、測試集維持原圖（反映真實資料）；若需要可勾「驗證集、測試集也增強」，同一張原圖的增強圖仍會留在它那一組。匯出紀錄會列出用了哪些增強（例如「水平翻轉、小角度旋轉 ±15°」）和只增強訓練集或全部，匯出紀錄和輸出確認也會分開列出原圖和增強張數，例如「訓練 70%（800 張 + 增強 1600 張）」，切分比例指的是原圖。增強圖檔名是 `原檔名_aug1.jpg`；增強後的匯出一定附圖片，COCO 會變成 zip（`images/` + json）。所有格式都適用。
- **匯出紀錄：** 列出每次匯出的序號、格式（含切分比例與張數）、類別、時間，可以下載或刪除（伺服器上的檔案會一起刪掉）。
- **從首頁匯入：** 首頁的「匯入」可以把圖片、影片和標註檔（COCO json 或 YOLO zip）一起匯入到既有或新的資料集。
- **影片：** 在「匯入」選影片（mp4、mov、avi、mkv、webm…），可以一次選多支。每支選好就先上傳，顯示長度、fps、總幀數和解析度，上方也會加總所有影片的總長和總幀數；每支可以拖曳滑桿或輸入時間（分:秒）設定擷取的開始與結束，瀏覽器能播放的格式還能用預覽畫面的目前時間當開始 / 結束。再設定每隔幾秒或每隔幾幀取一張（用幀數時不受影片 fps 影響），以及每支最多幾張，會即時顯示預計擷取幾張。上傳了但沒匯入的影片 24 小時後自動清掉。影格存成 JPG，放在以影片命名的子資料夾（例如 `cam1/cam1_000m01s000.jpg`，檔名是時間點），影片本身擷取完就刪除。影片會切成每塊 8 MB 分段上傳，網路斷掉的那一塊會自動重送，也不受反向代理單次上傳大小（例如 100 MB）的限制；單支上限 20 GB（`MAX_VIDEO_SIZE`）。直接選一個 YOLO 資料集資料夾（例如 `train/images`、`train/labels`、`data.yaml`，或 `images/`、`labels/` 的結構都可以）也可以，圖片和標註會一起匯入。
- **匯入 COCO：** 資料集頁面的「匯入 COCO / YOLO」上傳 COCO 格式的 json。圖片要先放好並掃描，會依檔名對應圖片（`file_name` 裡的資料夾會被忽略）。支援只有框的標註（例如 Roboflow、YOLO 轉出的 COCO）、多邊形、RLE 遮罩、關鍵點和旋轉框。匯入完成會跳出提示，有找不到的圖片等問題時，詳情在「任務」頁面。
- **匯入 YOLO：** 同一個按鈕上傳 zip，裡面放 YOLO 標註 `.txt`（資料夾結構不拘，例如 `labels/train/*.txt`）和 `data.yaml` 或 `classes.txt`（沒有的話類別會叫 `class_0`、`class_1`…）。依檔名（不含副檔名）對應資料集裡的圖片，所以圖片要先在資料集裡。標註類型預設自動判斷，也可以手動指定；detect 會變成框、segment 變成多邊形、obb 變成旋轉框、pose 變成框 + 關鍵點。

### 不經過網頁的轉檔

```bash
# COCO -> YOLO（--images 會順便把圖片複製到 out/train/images）
python scripts/coco_yolo.py coco2yolo coco-export.json out/ --task segment --images /path/to/images

# YOLO -> COCO（圖片尺寸從圖檔讀取）
python scripts/coco_yolo.py yolo2coco path/to/labels path/to/images coco.json --names data.yaml
```

需要 numpy、Pillow、PyYAML（obb 從多邊形轉換時需要 opencv）。

旋轉框在 COCO json 中的格式：

```json
"isrbbox": true,
"rbbox": [cx, cy, w, h, angle],
"segmentation": [[x1, y1, x2, y2, x3, y3, x4, y4]]
```

`angle` 的單位是度，在影像座標（y 軸向下）中順時針為正。`segmentation` 依序存 4 個角點，所以只認一般多邊形的工具也讀得懂。

YOLO-OBB 直接用上面的 YOLO 匯出（類型選 obb）。轉成 DOTA 格式：

```bash
python scripts/export_obb.py coco-export.json labels/ --format dota
```

## 設定

設定寫在專案資料夾的 `.env`（參考 `.env.example`），修改後執行 `sudo docker compose up -d` 生效。

| 變數 | 預設值 | 說明 |
|---|---|---|
| `SECRET_KEY` | — | 登入用的加密金鑰，**請務必設定一組隨機值** |
| `ALLOW_REGISTRATION` | `true` | 是否開放任何人註冊 |
| `DATASETS_DIR` | `./datasets` | 圖片放在主機的哪個資料夾 |
| `MODELS_DIR` | `./models` | SAM 和 YOLO 模型放在主機的哪個資料夾 |
| `SAM` | `none` | 建置時是否安裝 AI 功能：`none`、`cpu`、`cuda` |
| `SAM_CHECKPOINT` | `/models/sam2.1_b.pt` | SAM 權重檔；找不到時自動使用 `models` 資料夾裡最好的 SAM 檔案 |
| `COMPOSE_FILE` | — | 使用 GPU 時設為 `docker-compose.yml:docker-compose.gpu.yml` |
| `LOG_LEVEL` | `info` | 伺服器紀錄的詳細程度，除錯時可設 `debug` |
| `WEB_THREADS` | `300` | 同時連線數上限，每個開著的頁面佔用一個 |
| `SAM_CACHE_SIZE` | `64` | SAM 快取幾張圖的特徵 |
| `TRASH_DAYS` | `90` | 活動紀錄與垃圾桶保留天數，`0` 表示永久保留 |

## 從原版升級

原版使用 MongoDB 4.0，新版使用 MongoDB 7.0，資料庫需要一次性的遷移。請先看 [UPGRADE.zh-TW.md](UPGRADE.zh-TW.md)，步驟摘要：

```bash
cd coco-annotator                        # 原本執行 docker compose 的資料夾
sudo docker compose down                 # 停止舊版
git fetch && git checkout upgrade-2026
sudo ./scripts/migrate_mongo.sh          # 舊資料在 ./db 資料夾的話：sudo OLD_DIR=$PWD/db ./scripts/migrate_mongo.sh
sudo docker compose up -d --build
```

舊的資料庫完全不會被修改，隨時可以切回 `master` 退回舊版。舊帳號、密碼照常可以登入。

## 常見問題

**縮圖或圖片顯示「圖片不存在」**
資料庫裡有這張圖，但伺服器的 `datasets/` 資料夾找不到檔案（被刪除、搬走，或資料夾掛載路徑不對）。

**升級後打開網站叫我註冊，像是沒有任何帳號**
通常是 MongoDB 被強制關閉後統計數字沒更新。執行以下指令修正（只會檢查、更正統計，不會改資料）：
```bash
sudo docker exec annotator_mongodb mongosh flask --quiet --eval 'db.getCollectionNames().forEach(c => db.getCollection(c).validate({full: true}))'
```

**更新後畫面怪怪的，或紀錄裡出現 `unsupported version of the Socket.IO`**
瀏覽器還在用舊版網頁，按 `Ctrl+Shift+R` 強制重新整理。

**`git pull`、`docker compose build` 出現 `Could not resolve host`**
主機的 DNS 沒設定好。檢查 `/etc/resolv.conf` 裡有沒有 `nameserver`，有些校園網路只允許使用學校的 DNS。

**AI 工具是灰色的，或模型視窗顯示「沒有安裝模型支援」**
映像檔是用預設的 `SAM=none` 建置的，請參考[啟用 AI 功能](#啟用-ai-功能sam-與-yolo-預標註)重新建置。

**查看伺服器紀錄**
```bash
sudo docker logs annotator_webclient --tail 50
sudo docker logs annotator_workers --tail 50
```

**備份與還原**
`docker compose up -d` 會一起啟動 `annotator_backup`，每天自動備份資料庫到專案底下的 `backups/` 資料夾，保留最新 14 份（檔名像 `coco-2026-10-09_0300.archive.gz`）。第一次啟動、或伺服器關機超過一天後再開，會先立刻備份一份。可以在 `.env` 調整：

| 設定 | 預設 | 說明 |
|---|---|---|
| `BACKUP_HOUR` | `3` | 每天幾點備份（0–23） |
| `BACKUP_KEEP` | `14` | 保留幾份 |
| `BACKUP_DIR` | `./backups` | 備份放在哪個資料夾 |
| `BACKUP_TZ` | `CST-8` | 時區（台灣時間；POSIX 格式，例如日本為 `JST-9`） |

查看備份狀況：`sudo docker logs annotator_backup --tail 20`。

資料庫備份不包含圖片，`datasets/` 資料夾請另外保存（建議把 `backups/` 和 `datasets/` 一起定期複製到另一顆硬碟或另一台機器，備份放在同一顆硬碟上，硬碟壞掉時會一起不見）。

手動備份一份：
```bash
sudo docker exec annotator_mongodb mongodump --db flask --archive --gzip > backups/coco-manual-$(date +%F).archive.gz
```

還原（**會用備份覆蓋目前的資料庫**，建議先手動備份一份目前的）：
```bash
sudo docker exec -i annotator_mongodb mongorestore --drop --archive --gzip < backups/coco-2026-10-09_0300.archive.gz
sudo docker restart annotator_webclient
```

## 開發

```bash
# 後端測試（不需要 MongoDB、RabbitMQ）
cd backend && pip install -r requirements.txt mongomock pytest pytest-order && pytest

# 前端開發伺服器（熱重載）與測試
cd client && npm ci && npm run dev
npm test
```

或用 `docker compose -f docker-compose.dev.yml up --build`，開啟 `http://localhost:8080`。

| 部分 | 技術 |
|---|---|
| 後端 | Python 3.12、Flask 3、Flask-RESTX、Flask-SocketIO 5、Celery 5、MongoDB 7（MongoEngine）、RabbitMQ 4 |
| 前端 | Vue 3、Vite、Vuex 4、vue-i18n、Paper.js、Bootstrap 5 |
| AI | PyTorch、Segment Anything、Ultralytics YOLO（選用） |

介面翻譯檔在 `client/src/i18n/locales/`。
